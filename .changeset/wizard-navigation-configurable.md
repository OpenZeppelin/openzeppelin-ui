'@openzeppelin/ui-components': minor
---

`WizardNavigation`: new optional `previousLabel`, `previousDisabled`, `primaryLoading`, `primaryIcon` and `primaryIconPosition` (`'start'` puts the icon before the label, `'end'` is the default). The paged `WizardLayout` variants accept them too. An empty `previousLabel` leaves Back icon-only, and screen readers still announce it as "Previous". A loading primary button shows the kit spinner, sets `aria-busy` and ignores clicks while keeping focus. A disabled Back button uses `aria-disabled` and stays focusable. The navigation handlers (`onPrevious`, `onNext`, `onCancel`, `onLastStepSecondary`) now receive the click event, so you can restore focus after an async step. Existing zero-argument handlers still compile, and without the new props the navigation renders as before. `WizardLayout` passes the click event as an extra trailing argument to `onStepChange` (Next and Previous only; it is `undefined` for stepper clicks and scroll tracking), `onLastStepPrimary` and `onComplete`.

Behaviour change: in the paged `WizardLayout` variants, `onStepChange`, `onLastStepPrimary` and `onComplete` now receive the click event as an extra argument. A handler with its own optional parameter in that position (for example `onComplete={(force?: boolean) => …}` or `onStepChange={(index, options?) => …}`) now gets the event there and needs updating, as does a test spy that asserts exact arguments, such as `expect(onStepChange).toHaveBeenCalledWith(1)`.
