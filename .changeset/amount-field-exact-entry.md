`AmountField`: opt-in exact-entry mode for money values. With `formatOnBlur={false}` the typed text is never rewritten, and what the user types reaches the form as a decimal `string` that never passes through a float. A `number` or `bigint` from `defaultValues`, `reset` or `setValue` is shown exactly but is not converted on mount: it stays a `number` or `bigint` until the user edits the field, so seed the form with strings. Add `allowGrouping` to accept `,` thousands separators; the form value has them removed. Too many decimals (`decimals`), out-of-range values (`min` / `max`, which also accept strings for bounds beyond float precision) and malformed text are validation errors that block submit. Nothing is rounded. In this mode a `validateAmount` that returns `false` fails with "Enter a valid amount"; in the default mode `false` still passes, so return a message instead. Convert at submit with `parseUnits(value, tokenDecimals)`. The default mode also changes in this release: it now formats on blur and on the arrow keys exactly. New exported type: `AmountFieldExactProps`. `AmountField` now takes `AmountFieldProps | AmountFieldExactProps`, so a type derived with `ComponentProps<typeof AmountField>` sees `min` / `max` as `number | string`.
