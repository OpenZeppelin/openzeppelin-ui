`AmountField`: opt-in exact-entry mode for money values. With `formatOnBlur={false}` the typed text is never rewritten, and what the user types reaches the form as a decimal `string` that never passes through a float. A `number` or `bigint` from `defaultValues`, `reset` or `setValue` is shown exactly but is not converted on mount: it stays a `number` or `bigint` until the user edits the field, so seed the form with strings. Add `allowGrouping` to accept `,` thousands separators; the form value has them removed. Too many decimals (`decimals`), out-of-range values (`min` / `max`, which also accept strings for bounds beyond float precision) and malformed text are validation errors that block submit. Nothing is rounded. In this mode a `validateAmount` that returns `false` fails with "Enter a valid amount"; in the default mode `false` still passes, so return a message instead. Add `groupedDisplay` (with `allowGrouping`) to show the value with thousands separators while the field is not focused (`250,000.00`) and plain while it is being edited (`250000.00`); the separators are display only and the form value stays plain. With `groupedDisplay`, a correctly grouped string from `defaultValues`, `reset` or `setValue` is stored without its separators right after it arrives, which marks the form dirty, so seed plain strings to keep the form pristine. A read-only or disabled field stays grouped on focus and is never written, so seed read-only amounts plain. On that same grouped input, add `restrictInput` to refuse keystrokes and pastes that break the amount grammar or go past `decimals` (Backspace, Delete and clearing a selection still always apply), and add `padDecimals` to pad the unfocused grouped display to `decimals` places (`123000` shows `123,000.00` when decimals are 2) while focused editable text stays unpadded plain. Both are off by default. In exact-entry mode, `validation.messages` can replace the malformed-text (`format`), too-many-decimals (`decimals`), below-`min` (`min`) and above-`max` (`max`) texts; `min` and `max` follow the field's `min` / `max` props, not `validation.min` / `validation.max`. A misconfigured `decimals`, `min` or `max` still shows "Amount limit is misconfigured". Convert at submit with `parseUnits(value, tokenDecimals)`. The default mode also changes in this release: it now formats on blur and on the arrow keys exactly. New exported type: `AmountFieldExactProps`. `AmountField` now takes `AmountFieldProps | AmountFieldExactProps`, so a type derived with `ComponentProps<typeof AmountField>` sees `min` / `max` as `number | string`.
